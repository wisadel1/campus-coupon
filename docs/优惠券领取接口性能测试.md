# 优惠券领取接口性能测试

## 1. 测试目标

对优惠券领取接口进行压力测试，观察在一定并发请求下的响应时间、吞吐量和 JMeter 错误情况，为后续性能分析与优化提供数据。

本次测试接口：

- 请求方式：`POST`
- 请求路径：`/api/coupon/claim`
- 请求体：包含 `templateNo` 和 `userId`

## 2. 测试环境与配置

| 配置项 | 参数 |
|---|---:|
| 并发线程数（Threads） | 100 |
| Ramp-up | 2 秒 |
| 每线程循环次数（Loop Count） | 5 |
| 计划请求总数 | 500 |
| 用户 ID 范围 | 1001～1500 |
| Keep-Alive | 开启 |
| 请求方式 | POST |
| 请求路径 | `/api/coupon/claim` |

本轮使用不同用户 ID 参数化请求，避免因同一用户重复领取而使测试结果受到重复领取业务规则的干扰。

## 4. 结果分析

### 4.1 整体响应时间

本轮平均响应时间为 8.39 ms，中位数（P50）为 4 ms，说明大部分请求能够在较短时间内完成。

### 4.2 吞吐量

本轮吞吐量为 267.67 次/秒。在 100 个并发线程、计划发送 500 次请求的条件下，JMeter 汇总结果中未记录错误。

需要注意，吞吐量是本次测试环境和负载配置下的观测值，不应直接视为系统在任意环境下的稳定处理能力或最大容量。

### 4.3 长尾延迟

P95 为 13.95 ms，而 P99 为 179 ms，最大响应时间为 180 ms。两者差距较大，说明少量请求存在明显的长尾延迟。

潜在影响因素包括数据库查询与写入、事务提交、Redis 操作、线程调度以及测试环境资源竞争等。仅凭本次汇总数据无法确定具体瓶颈，需要结合应用日志、数据库指标和 Redis 指标进一步分析。

## 5. 与 M7 模板详情缓存测试对照

此前 M7 缓存命中稳定轮的代表数据如下：

| 指标 | M7：模板详情缓存命中 | M8：优惠券领取 |
|---|---:|---:|
| 请求数 | 500 | 500 |
| JMeter 错误率 | 0% | 0% |
| P50 | 1 ms | 4 ms |
| P95 | 3 ms | 13.95 ms |
| P99 | 19.84 ms | 179 ms |
| 吞吐量 | 261.10 次/秒 | 267.67 次/秒 |

两组测试的业务逻辑不同：M7 主要验证模板详情缓存命中对读取请求的影响；M8 则涉及领取流程中的 Redis 库存预扣和数据库写入。因此，这些数据适合用于记录不同场景的测试表现，不适合据此直接判断两个接口谁的性能更好。

M7 另有数据库 SQL digest 统计：在测试期间没有其他相同 SQL 干扰的前提下，无缓存测试后目标 SQL 计数增加 498，而随后缓存命中测试计数未继续增加。这支持缓存命中减少目标数据库查询的判断。

## 6. 阶段性结论与限制

本轮测试中，JMeter 汇总结果显示 500 次请求、0 次工具判定失败，平均响应时间为 8.39 ms，吞吐量为 267.67 次/秒。测试数据初步反映了当前环境下领取接口在该负载配置中的性能表现。
