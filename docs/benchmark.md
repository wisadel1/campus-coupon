# M2 券模板详情接口无缓存性能

## 1. 测试目的

本次测试针对 M2 阶段实现的券模板详情接口，建立无缓存情况下的性能基线，为后续 M7 阶段引入 Redis 缓存后的性能优化提供对比依据。

测试接口：

```http
GET /api/template/{templateNo}
```

当前接口每次请求均直接查询 MySQL，未使用 Redis 缓存。

本次测试主要记录以下指标：

- **Throughput**：接口每秒处理的请求数量。
- **P99 延迟**：99% 的请求能够在该时间内完成。
- **DB 查询次数**：通过 MySQL 全局状态变量 `Com_select` 统计压测期间的 SELECT 语句数量变化。

## 2. 测试环境与配置

### 2.1 测试工具

- 压力测试工具：Apache JMeter
- 后端框架：Spring Boot
- 数据库：MySQL
- 缓存：本次测试不使用 Redis 缓存

### 2.2 JMeter 配置

| 配置项 | 参数 |
|---|---|
| 接口类型 | GET |
| 接口路径 | `/api/template/{templateNo}` |
| 请求参数 | 真实存在的 templateNo |
| 线程数 | 100 |
| Ramp-up Period | 2 秒 |
| Loop Count | 5 |
| 总请求数 | 500 |

所有请求均指向同一个真实存在的券模板编号。

## 4. 测试结果分析

本次无缓存测试中：

1. JMeter 共发送 500 次请求，错误率为 0%，说明接口在本次测试负载下能够正常处理请求。
2. 平均响应时间为 3 ms，最大响应时间为 34 ms，整体响应较快。
3. 吞吐量约为 251 requests/sec，表示本次测试条件下接口平均每秒完成约 251 次请求。

需要注意，本次测试是在特定软硬件环境和并发配置下完成的，测试结果不能直接代表生产环境的最大处理能力。

## 5. 后续优化方向

在 M7 阶段计划为券模板详情接口引入 Redis 缓存，采用缓存优先、数据库兜底的查询方式。

预期通过 Redis 缓存减少数据库查询压力，降低接口响应延迟，提高接口吞吐量。

## 6. 结论

本次测试建立了券模板详情接口在无缓存情况下的初始性能基线。

后续将以本次测试的线程数、Ramp-up 时间、循环次数及请求参数作为统一测试条件，对比 Redis 缓存引入前后的性能变化，并通过吞吐量、P99 延迟和数据库查询次数验证缓存优化效果。
